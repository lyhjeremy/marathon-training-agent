An agent loop with a code-based critic

A training-plan agent that checks its own plan before you see it

Asked for a 3:05 Boston off 22 miles a week, it recommended 3:20, and its critic caught five problems in the first draft before anyone saw it. The agent is a LangGraph state machine with five nodes. It judges whether the goal is realistic, drafts a periodized week-by-week plan, and tailors it to the race and the forecast heat. Then deterministic safety checks in Python run alongside an LLM review, and a revise node fixes whatever they flag and loops back, up to a revision budget.

Why a graph

A single prompt can't check its own arithmetic

Ask a language model for a sixteen-week marathon plan and the result looks right, even when it raises mileage 30% in a week, skips the taper or prescribes a 26-mile long run. A coach would spot those errors at a glance; in fluent prose they are easy to read past.

The graph adds a place to catch them. The critique node runs _safety_checks, which reads the plan's numbers and returns a list of problems, and merges that with issues an LLM reviewer raises. _route sends the plan to revise when there are issues and revisions remain (two by default), and ends the run otherwise.

assess
Judges whether the goal is realistic for the runner's mileage, longest run and weeks to go; returns a recommended goal time and a peak weekly mileage as JSON.
plan
Drafts the Base, Build, Peak and Taper weeks in a fixed JSON schema: miles, long run, quality sessions, focus.
adjust
Rewrites workout emphasis for the race using src/knowledge.py: a simulated course penalty against Berlin, about 1 minute per °F above 55°F, and the 30 km wall.
critique
Deterministic checks plus an LLM review; the plan passes only with zero issues.
revise
Fixes the listed issues and returns the full plan to critique.

Interfaces

CLI and a Streamlit app

python -m src.cli takes flags or prompts for them and prints the assessment, the plan table and the trace. streamlit run app.py wraps the same graph: set the race in the sidebar and watch the run stream through the nodes, then read the plan table, a weekly-mileage chart, the safety verdict and the trace. Generation uses the Claude CLI by default or the Anthropic API with ANTHROPIC_API_KEY; CLAUDE_MODEL can pick a faster model for the several calls a run makes. There is no hosted demo.

Limitations

Evidence from a single run

src/eval.py is written to measure whether the loop makes plans safer: it runs three synthetic runners (two deliberately aggressive, one realistic control) and scores each plan with the same _safety_checks before and after the loop. Those results have not been captured; the run was cut short by CLI rate limits during the build. This page shows one recorded run in which the critic caught five issues, which says nothing about the average lift.

The deterministic checks cover four rules. Anything else, such as too many hard days or a monotonous build, depends on the LLM reviewer. The plan is generated advice for an adult runner and is no substitute for coaching or medical guidance.

The course figures in src/knowledge.py are simulated. They come from an earlier version of my Majors course-difficulty simulation, which ran on a simulated field with course penalties planted in code, so they are not measurements of the courses, and they differ from the current study: the file has London at 28 s and Tokyo at 33 s against Berlin and a Boston index of 1.036, where the study's paired method gives 30.7 s, 21.0 s and a composite of 1.0092. The file says so in a comment, and the course line it passes to the adjust prompt now calls the figure a simulated estimate, not a race result. They only steer the wording of adjust, and none of the safety checks reads them.
