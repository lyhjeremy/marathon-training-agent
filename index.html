A marathon plan that has to pass review

By Jeremy Lee. Tell it your race, goal, current mileage and weeks to go.

The model drafts the plan; plain Python checks it. critique flags any week that raises mileage more than 20%, a race week above 75% of peak, a long run over 22.5 miles, or a long run longer than the week, and merges that with an LLM review. revise fixes what was flagged and loops back, up to two revisions by default.

The five nodes

  • AssessIs the goal realistic for this fitness and timeline? Returns a target time and peak mileage.
  • PlanDrafts Base, Build, Peak and Taper weeks as JSON.
  • AdjustTailors the plan using course penalties (Boston +101 s against Berlin), about 1 minute per °F of heat, and the 30 km wall, from my own marathon analyses.
  • CritiqueFour deterministic checks plus an LLM review.
  • ReviseFixes the listed issues and sends the plan back to critique.

Runs from the command line or a Streamlit app that streams each node. Generation uses the Claude CLI by default or the Anthropic API. An evaluation harness (src/eval.py) is written but its results haven't been captured yet.
